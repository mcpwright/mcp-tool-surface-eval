# Few-tools experiment — results (2026-06-04)

Tool-selection accuracy on the 17-task EDGAR set, 5 trials per (task, surface),
`tool_choice: any`. Control = edgar as shipped (11 tools); Fragmented = the same
capability un-collapsed into 26 narrow tools. Exact-match scoring, no execution.

| Model | Control (11) | Fragmented (26) | Gap | Control CI | Fragmented CI |
|---|--:|--:|--:|--:|--:|
| claude-sonnet-4-6 | 100% (85/85) | 94% (80/85) | +6 pts | 96–100% | 87–97% |
| claude-haiku-4-5  | 93% (79/85)  | 92% (78/85) | +1 pt  | 85–97% | 84–96% |

## Reading these honestly

**The few-tools principle is NOT well-supported on the tool-selection metric.** The
gaps are small (6 pts, 1 pt) and the 95% CIs overlap in both models — at this N there
is no statistically meaningful difference. A capable model picks correctly from a
26-tool fragmented surface about as well as from the tidy 11-tool one. The prediction
that a weaker model would show a *larger* gap did not hold: Haiku's gap is smaller
than Sonnet's.

**What the data does show** is a specific failure mode, not a general accuracy drop:

- `list_s1` ("List the S-1 registration statements filed by Reddit") — on the
  fragmented surface the model is repeatedly lured into `lookup_issuer_by_name` first,
  a plausible "resolve the company, then…" detour that the parameterized `list_filings`
  tool lets it skip. (Haiku fails S-1 on *both* surfaces, so part of this is
  task-framing, not fragmentation.)

**Implication for the essay.** The honest takeaway is that the value of few orthogonal
tools is *not* primarily single-shot selection accuracy — it's token overhead (26 tool
schemas vs 11 in context every turn), robustness across multi-step tasks (error
compounding this eval doesn't measure), and avoiding tempting wrong detours. The claim
should be refined accordingly rather than asserted as a selection-accuracy win.

## Caveats

- **Selection only** — the model picks one tool; nothing is executed. Real cost
  differences (tokens, latency, multi-step compounding) are out of scope here.
- **N = 85 per arm** (17 tasks × 5 trials). CIs are wide; treat single-digit gaps as
  noise.
- Scored tasks target only genuinely-distinct splits (form / metric / side / report
  type). The fragmented surface's intent-splits (lookup-by-ticker/name, search scope)
  add distractor load but are not themselves scored.
- The per-task ✓ column marks a task correct only if **all** trials were correct;
  the tool shown is the majority pick. A correct-tool name beside an ✗ means the
  majority was right but not unanimous.

_Reproduce: `ANTHROPIC_API_KEY=… uv run mcp-tool-surface-eval few-tools --client anthropic --model <model> --trials 5`._
